# DSH Evolith 记忆插件

**0.18.14 · 普通插件 · Evolith 默认开启，可随时关闭或重新开启。** 包名保持 `dsh-memory-bridge-profile`，复用 DSH 已有工作区和会话，不创建独立 Desktop 工作台。

## 使用

1. 安装插件并重启 DSH。进入“设置 → 记忆”，保存服务器地址和访问密钥。
2. 新版独立后台：`http://192.168.106.20:28292/workbench`。注册后自动创建默认记忆组和默认访问密钥；在网页查看/复制密钥，填入插件即可，无需 Group ID。原 28192 后台不受影响。
3. 同一账号的全部有效密钥共享一个默认 Evolith 记忆组；不同账号隔离。20 服务器已于 2026-11-23 将旧 28192 的账号、访问密钥和记忆迁移到新版 28292；同账号各工作区记忆合并为默认组，同名账号保留旧密码及新版已有记忆。记忆提炼统一使用服务端管理的 `deepseek-v4.1-flash-1017`，用户无需配置模型或模型密钥。
4. **Evolith 默认开启**，没有保存过开关状态的会话直接启用；手动关闭过的会话保持关闭。问号悬浮说明数据范围。可随时关闭或重新开启。
5. 关闭后取消后续上传和记忆管理；切换连接会撤销旧连接授权并取消正在发送的请求，需重新确认开启。已收到的服务端数据和插入本地的历史记忆不会自动删除。

现有连接配置保留。若旧版配置仍指向 28192，需要手动改为新版地址；迁移后的旧账号访问密钥可直接使用，无需重新注册或配置模型。切换服务或密钥会撤销已开启会话的授权，需要重新选择开启。

## 数据与界面

- 关闭的会话不执行 Evolith 检索、写入、历史同步、工作区扫描或诊断上传。仅安装插件、打开设置或切换开关不会上传会话。
- 开启后，整个 session 的公共对话内容（包含已有历史、用户消息、模型回复及工具调用/结果）会发送给所配置的服务端保存和提炼。不发送 Actor 隐藏 reasoning 或图片二进制；图片在轨迹中标为占位。
- “检查连接”是用户主动发起的账号检查，不包含会话内容。“记忆管理”打开后台网页，不把访问密钥放进 URL。
- 记忆设置只保留标题、管理入口和线上连接配置；下方仅默认折叠的**本地错误日志**。日志不上传到记忆后台。DSH 自身的其他遥测设置由宿主管理。

## 记忆逻辑

沿用 Evolith 当前方法：N8/B4、每四轮冻结一次 Top40、BM25 完全同文去重、当前 query 加全历史七段分层抽样、仅当前批最多四轮公共轨迹、O/F/P 各一次、neutral。不自动判断回答正确与否。

每段窗口保留 8–11 个 DSH 原生业务轮，工具步骤不另算轮。新检索的增量记忆追加在当前用户消息之后，既有消息不改写；只有窗口移动或原生压缩会替换旧的 surface 区域。移出前必须等覆盖该历史的 writer 提交。原生压缩保留宿主触发策略，但仅允许在同一轮内压缩，不跨记忆边界或业务轮。短会话不足四轮时后台保存，空闲两分钟后提炼。写入失败保留证据并在下一轮报错，不丢弃未提交历史。

每条新用户消息先按旧版弱监督规则判断上一段回复的反馈，得到 positive / negative / neutral，然后统一进入反馈入口。正负反馈结算本 session 自上次有效反馈以来曝光的记忆；neutral 持续累积。待反馈集合按 session 隔离，记忆和汇总统计仍按账号共享。它是对用户反馈的推断，不是标准答案评分。

判断在本轮检索、注入之前完成；没有前序回复时跳过模型，按 neutral 处理。判断失败保留待反馈集合并报错，不当成 neutral；重试复用已保存的判断，避免重复计分。客户端先确保旧曝光记录送达，再准备下一轮；曝光重试仍失败则阻止后续推理。未送达请求保存在本机权限为 0600 的待发送文件中，重启后仍先补送，且绑定当前服务和访问密钥；关闭或切换连接会清理对应待发送队列。三种反馈共用原有 B4 writer，不会因为正负反馈额外提炼，也不启用 UCB、降权或自动重写。

后端已保存的旧账号级 pending 不会猜测归入某个 session，之后按新曝光建立 session 反馈区间。

## 安装与验证

在 DSH Desktop 的“插件 → 添加插件”输入以下 GitHub 仓库地址即可安装当前版本：

```text
https://github.com/dataelement/dsh-memory-bridge
```

首次安装及旧版更新见[快速上手](docs/quickstart.zh-CN.md)。

已有旧版时，先在插件列表卸载 `dsh-memory-bridge-profile`，再通过上面的仓库地址安装，并完全退出后重新打开 DSH Desktop。工作区、会话和连接配置保留；原 28192 地址需要改为 28292，检查连接后按会话重新开启 Evolith。

```sh
npm ci --ignore-scripts
npm test
npm pack --pack-destination release
```

本版已用独立 DSH Web profile（内核 0.2.0-rc.2）实际加载与检查 UI，并用 0.2.0-rc.2 / 0.2.1-rc.2 / 0.2.2-rc.1 原生 Session 验证公共工具轨迹、窗口替换及固定 system 指令。其他声明版本仍需安装验收，不宣称已完成 Windows 真机验收。Node 推荐 22.19+。

服务端源码独立保存在相邻的 `evolith-memory-service` 工程，**不包含在本插件安装包中**。本仓库不提交数据库、真实用户会话、真实密钥或服务器环境文件。自动化测试仅包含合成 BizAgentBench 的固定回放样例，且不随插件安装包发布。错误日志仅本机内存保存，最多 200 条，重启清空。

## 0.17.3 输入框控件

Evolith 改为紧凑的滑动开关与矢量帮助图标。帮助说明通过页面浮层显示，鼠标悬浮、键盘聚焦或点击均可打开；移开、Escape、页面滚动或窗口尺寸变化时关闭。浮层避开输入框裁剪并按视口定位，兼容当前 DSH 主题。帮助操作不改变授权，也不触发任何记忆请求。记忆及弱监督逻辑保持不变。

### 0.17.4：隐藏聊天中的记忆注入块

Evolith 注入消息只参与模型上下文，不在聊天气泡中展示。按插件生成的消息 ID 隐藏，已有会话也生效；用户原文、模型回复及服务端记忆处理保持不变。

## 统一测试

所有插件单元测试、当前 Desktop 内核兼容检查和 BizAgentBench 第22题集成回放均随仓库源码管理，无需依赖临时目录中的测试脚本。**安装或升级插件不自动运行测试；仅手动执行测试入口时运行。**

```sh
npm ci --ignore-scripts
npm test
```

也可直接执行 `./scripts/test.sh`，入口与 `npm test` 相同。macOS 自动使用已安装 DSH Desktop 的 Node 和内核；其他环境用 `DSH_TEST_NODE`、`DSH_KERNEL_ROOT` 指定运行时和完整内核。默认完整运行，环境缺失按失败报告，不会静默跳过。

- `npm run test:unit`：只运行语法和单元测试，报告明确标记未运行的集成阶段。
- `npm run test:bizagent`：只运行 BizAgent 回放。
- 每次生成 `test-results/<时间戳>/index.html`、`report.json`、分阶段日志及逐轮事件。`test-results/index.html` 指向最新报告，`latest.json` 提供机器可读指针。
- 终端显示各阶段结果、通过/失败/取消数量和报告位置；有阶段失败、超时、结果缺失或统计不一致时退出码为1。报告支持CI收集，不自动打开浏览器。
- 测试源文件位于 `test/`、`tests/integration/bizagent/`，统一运行器位于 `scripts/`；合成fixture、测试依赖和生成报告均不进入插件发布包。

完整覆盖、测试替身和限制见 [测试说明](tests/README.md)。这些测试不发起真实模型调用，不上传生产记忆，不修改用户正在使用的 Desktop。

## 当前会话的记忆使用记录

仅在开启 Evolith 的会话中提供 `evolith_record_verified_memory`（沿用工具名）。入参是 `memory_id`、`title`、`usage_summary`、`benefit_type`，全部必填。`benefit_type` 为 `avoid_error` / `save_tool_calls` / `both`，分别表示避免问题、节省调用、两者都有。只有实际使用记忆规避了具体潜在错误，或节省了重复查询/读取/搜索，才在最终答复前调用。用途说明必须写清具体错误或复用的信息，不虚构节省时长，不为记录额外查询。

程序根据 ID 在本会话实际注入记录中取最后一次送达的版本，保存原文、版本、来源和使用轮次；拒绝其他会话/未注入的 ID。记录表示 Actor 报告的使用价值，不等于独立验证或正确率，不提交正反馈、不改变 UCB、不重写记忆。

当前轮工具成功返回后才自动打开“记忆使用记录”，每轮至多一次。历史加载、失败及开启开关不触发展开；支持手动查看。新记录展示记忆内容与具体帮助，原文及来源默认折叠；旧验证记录及证据继续兼容显示，按账号及会话隔离。

### 0.18.1：按结果展开与易读卡片

侧栏自动展开监听本地会话的实时工具结果，不根据记忆数量轮询判断，也不因加载旧记录而展开。切换会话时解除旧订阅；只处理当前会话本轮的成功验证返回。

验证工具新增短标题、用途概括、核实概括三个字段，要求用用户语言写成简短通俗文案。卡片优先展示结论、“帮了什么忙”和“如何确认”；记忆编号、原文、技术日志及完整解释默认收进“查看原文与证据”。旧记录兼容展示，不重写已有的证据内容；“尚无评测反馈”类旧记录提供对应的通俗标题和概括。

### 0.18.2：卡片明确区分记忆内容和核实状态

标题展示记忆实际表达的内容，核实状态仅作角标；移除空泛占位标题和自动补出的泛化核实说明。旧记录直接展示保存的原文，已知批次元信息提供忠实的中文释义。无短核实摘要时仅列实际证据类型，完整过程默认折叠。用途区缩短为三行预览，去掉大面积底色。自动展开条件不变。

### 0.18.3：精简记忆卡片

移除卡片正文的“核实依据”区域，保留记忆内容和本次用途。完整核实说明与证据仍在“查看原文与证据”中，默认折叠。仅调整展示，不改变验证工具和记录。

### 0.18.4：窗口移出记录可持久化重开

补齐 `compaction/prune.data.shadowedSeqs`，精确记录当前表面中移出的消息序号。BizAgent 回放每轮写入真实 zstd 文件，经过当前 DSH 严格格式加载器重开，核对全部事件、窗口和模型消息不变。新增显式离线修复工具 `scripts/repair-session-log.mjs`：默认只读验证，仅在指定 `--apply --backup-dir` 时完整备份、校验并原子替换；只恢复有紧邻替换记录可验证的缺失字段，不删除事件。原始日志的多帧内容全部解压验证，修复可重复执行。安装不运行测试或自动修复用户会话。

### 0.18.5：保留中立版记忆验证提示词

将此前只在本地安装目录修改的中立版提示词纳入源码。明确“使用”包含记忆内容出现在最终回答或实质影响回答；实际使用且有独立来源复核时记录。重新阅读曾经看过的原始论文、文件、数据库仍可构成独立证据，复述自己的旧回答不能。未使用、仅检索到、仅凭历史成功率或复核矛盾时不记录。工具描述和会话系统提示共用同一份指令；本地记录不自动作为正反馈。

### 0.18.6：明确记忆密钥错误

记忆密钥未填写或服务端返回 401 时，在会话失败提示及连接检查中明确说明是 Evolith 记忆访问密钥问题，并引导到「设置 → 记忆」更新、保存和检查连接，区分聊天模型密钥。

### 0.18.7：密钥保存状态更清晰

已配置访问密钥时，输入框显示 `****` 占位符、标签显示“已保存”；未配置时提示“请输入访问密钥”。占位符不是密钥值，留空保存仍保留原密钥。

### 0.18.8：Evolith 默认开启

没有保存开关状态的会话默认启用；保留明确保存的关闭选择和账号切换隔离。设置和悬浮说明同步更新，原有隐私说明、关闭后不上传及密钥校验保持有效。

### 0.18.9：会话内开启后锁定

默认开启的会话和手动开启的旧会话均不能再通过界面或本地 API 关闭；开关提供锁定说明。切换连接仍撤销旧账号授权，避免跨账号发送。

### 0.18.10：兼容会话中途开启 Evolith

窗口移出时保留历史中间新增的系统提示，并按其两侧的连续过期消息分别移出。新增第一轮关闭、第二轮开启和前五轮关闭、第六轮开启的46轮真实内核回放，逐轮检查记忆注入、系统提示、工具、窗口和持久化重开。

### 0.18.11：恢复随时关闭和重新开启

取消0.18.9的会话锁定，前端开关和后台接口均支持关闭及重新开启。默认开启保持不变，显式关闭会持久化；保留中途开启窗口修复。新增关闭第二轮、第三轮重新开启的46轮真实内核回放。

### 0.18.12：三字段记忆使用记录

简化入参，由程序按ID获取本会话实际注入的最新版本。用途摘要说明避免的潜在错误或省去的重复查询；新记录不再标为已核实，旧证据仍可查看。

### 0.18.13：记忆收益 BUFF 标识

卡片按用途摘要明确表达的收益，显示蓝色盾牌“避免问题”及金色闪电“节省调用”；两者可同时显示。单纯复用信息不算省调用，否定表述不点亮。分类只使用已保存摘要，不增加工具入参或模型请求；标识代表助手的说明，不是实际调用差值测量。

### 0.18.14：收益类型由模型必填

新增必填枚举 benefit_type，前端只按显式类型显示BUFF，删除关键词推断。用途摘要仍需描述具体帮助；已执行的同一查询不能算作节省。旧记录没有类型时保持原文，不猜测、不自动补分类。
