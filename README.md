# dsh-memory-bridge
# DSH Memory 普通插件

为 DSH 已有的工作区和会话连接公司内网记忆服务。当前版本：**0.16.4**。

本版只提供普通插件功能和“设置 → 记忆”页面，不注册独立 DSH 工作台。继续使用原来的工作区、会话和已保存的连接配置。

## 在 DSH 中安装

打开 DSH 的“插件 → 添加插件”，填写公司插件仓库地址即可安装：

```text
https://github.com/dataelement/dsh-memory-bridge
```

该地址使用仓库默认分支中的版本。本仓库只包含普通客户端插件，DSH 可以通过内置插件安装流程直接安装；无需手动编译，也不要求迁移工作区和会话。

如果已安装同名旧版，先在 DSH 插件页面卸载旧版，再安装并启用本版。不要选择删除连接配置、工作区或会话数据。保存当前工作后，使用“应用 → 重启”加载新代码；仅刷新界面可能继续使用旧插件。旧的 `dsh-memory-bridge` 与本包不能同时启用，以免重复读写。

本版包名仍为 `dsh-memory-bridge-profile`，沿用现有配置。安装本插件不会自动卸载其他插件，也不会删除工作台市场留下的历史条目。

## 让 DSH 的 AI 协助安装

在支持插件管理工具的“创作者”模式中，把安装地址和以下要求发送给 AI：

> 请使用 DSH 自带的插件管理功能安装这个普通记忆插件，保留我的工作区、会话和 Memory 连接配置。先检查是否已有同名版本，按实际情况处理升级；不要注册或创建独立工作台。需要批准或重启时请提示我。

安装工具的开放情况和权限要求由目标 DSH 决定。工具不可用时，使用“插件 → 添加插件”页面安装。

## 安装后使用

1. 在“设置 → 记忆”保存服务器地址和个人 Memory 访问 Key（插件连接记忆服务的密钥，与聊天模型密钥不同），然后检查连接。
2. 选择 DSH 中已经存在的工作区与会话。
3. 选择记忆组并确认绑定；确认后才按原规则处理选中的历史会话。
4. 点击“记忆管理”，在 DSH 内置浏览器打开服务器网页；关闭设置即可查看登录页。未提供内置浏览器的旧版会使用系统浏览器，也可直接点击“系统浏览器打开”。登录使用网页账号，不会把插件访问密钥放到网址中。

插件不扫描项目文件正文。未加入的工作区、未选择的会话和暂未绑定记忆组的工作区不会启用记忆处理。不要把“安装成功”当成“已经生成记忆”。

服务器已有的 `/workbench` 管理网页与 DSH 独立工作台是不同功能，本插件保留该网页入口。

## 运行条件

- 兼容目标：Windows x64，DSH Desktop 0.12.1（内核 **0.2.1-rc.2**）与 DSH Desktop 0.14.0（内核 **0.2.2-rc.1**）。两套内核依赖均经过自动化回归测试；其他版本需先验证。
- 需要能够访问配套 Memory 服务，管理接口版本 **0.10.0**。
- 默认服务器地址为公司内网 `http://192.168.106.20:28192`，可在记忆设置页更改。每个人填写自己的访问 Key，包内不包含真实密钥。
- macOS 和其他内核版本尚未完成真机验收。

## 当前整体关系

```text
原有 DSH 会话
  → 插件读取相关记忆并加入本轮对话
  → DSH 按原有方式调用聊天模型
  → 插件回传对话和反馈
  → Memory 服务按原规则提炼、检索和保存
```

`client.js` 提供普通插件的记忆设置页面；`index.js` 和 `src/` 连接原有会话与记忆服务；记忆服务器负责权限、提炼、检索和持久保存。

【实现层】0.15.0 恢复普通插件入口，并提供可直接安装的公开仓库地址和 `.tgz` 包；不改变反馈判断、记忆提炼和检索规则。

## 失败重试与诊断日志（0.16.0）

- 历史上传和实时同步失败都会保留待重试任务。网络、超时、限流、模型格式错误最多额外自动重试 5 次，间隔为 5、15、45、120、300 秒；插件每 15 秒扫描一次，因此实际触发可能稍晚。
- 缺少记忆模型时暂停，模型配置恢复后自动继续。DSH 与插件需要保持运行；关闭后再次启动会恢复检查。
- 在“会话处理与失败重试”中，可以重试单批或全部失败会话。只处理失败部分，已完成和已在后续同步恢复的会话不会重复上传。手动重试会重新开始该会话的重试额度。
- 密钥、权限、额度不足和绑定变化需要先修正。切换账号、服务器、记忆组或取消会话选择后，原任务不会按旧授权继续上传。
- 没有有效反馈、没有新反馈、重复内容是正常完成，不因为 0 条记忆而重复提炼。反馈判断和记忆提炼方法保持原样。
- 公司服务升级到 0.16.0 后，管理员在“诊断日志”查看所有账号的处理记录，按用户、空间、组、工作区、会话、阶段、请求和处理链筛选，查看详情或导出 NDJSON（每行一条完整日志的文本文件）。普通用户与访问密钥无法读取管理员日志。
- 日志包含实际提交的完整处理输入、模型原始响应、判断/保存结果、运行版本、耗时、错误堆栈及每次重试。仅采集已选会话相关的记忆处理，不扫描未选会话或项目文件。密码、模型密钥、访问凭证会脱敏；离线失败输入和诊断事件会在本机保存，原账号连接恢复后补传，不跨账号发送。
- 默认不自动清理服务端日志。部署前的未记录过程不能补齐；旧插件没有上报的本机错误也不能由服务器凭空还原。

## 0.16.1 修复说明

- **新版 DSH 保存配置**：兼容 Desktop 0.14.0 从 `dsh-app://app/` 转发时缺少 Origin（请求来源地址）的写入请求。插件页面增加专用请求头；服务端仍检查本机连接、本机 Host、转发头和显式来源。不会开放跨站访问，也不会接受不带标记的无来源写入。
- **任务项目名称**：从任务详情中的会话标识恢复真实工作区名称，并显示会话标题。同组多个项目分别匹配，重启后仍能恢复；读取相关工作区的会话目录，不读取会话正文，只关联已选会话。已取消选择、已删除或无法对应的记录标为“组内历史记录（来源未识别）”，不猜测项目。
- **内置浏览器登录页**：通过 DSH 官方 `sidebarRight.openTab('browser', …)` 打开真实服务器网址，避免内部地址的新窗口和重定向被桌面端拦截。保留系统浏览器入口，不改变登录方式。
- **状态展示**：已完成的服务器结果不会继续被旧的本地“等待处理”遮住；同一任务只显示一次。

【实现层】以上修改仅涉及桌面端兼容、名称关联和显示。包名、已有配置文件、工作区归属、会话选择、反馈判断、提炼及检索方法保持不变。名称概览最多补查当前可见的 8 个任务，并在当前账号连接期间复用任务标识；切换账号或服务器会丢弃该缓存。
